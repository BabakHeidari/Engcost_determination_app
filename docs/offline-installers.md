# نصب و اجرای محلی و آفلاین (PR-11)

نسخه بسته‌بندی: `0.11.1`. این راهنما برای بسته آزمایشی بدون امضا است.
بسته‌های واقعی [ویندوز](https://github.com/BabakHeidari/Engcost_determination_app/actions/runs/38463009134/artifacts/11848591222)
و [اوبونتو](https://github.com/BabakHeidari/Engcost_determination_app/actions/runs/38463009134/artifacts/11847451795)
را دریافت و فایل ZIP را باز کنید. نصب‌کننده، checksum و گزارش‌ها داخل آن هستند.
اگر بسته قبلی در فرم راه‌اندازی خطای Forbidden می‌داد، همین نسخه را روی نصب
قبلی نصب کنید؛ پوشه workspace را حذف نکنید. [جزئیات اصلاح](pr11-setup-form-fix.md).
آزمون نصب و اجرای آفلاین در Windows Server 2022 و Ubuntu 22.04 موفق بوده است؛
بررسی دستی Desktop ویندوز ۱۰/۱۱ و اوبونتو و تأیید مالک هنوز باقی است.
جزئیات در [گزارش اعتبارسنجی](pr11-validation.md) آمده است.

## نصب و اولین اجرا

۱. در ویندوز فایل `Engcost-0.11.1-Setup.exe` را باز کنید. نصب برای همان کاربر
انجام می‌شود و نشان Engcost در Desktop و Start Menu ایجاد می‌شود. در اوبونتو
فایل `engcost_0.11.1_amd64.deb` را با ابزار نصب بسته سیستم باز کنید؛ تأیید عادی
مدیر سیستم برای نصب قابل قبول است. سپس Engcost را در فهرست برنامه‌ها باز کنید.

۲. مرورگر پیش‌فرض خودکار باز می‌شود. «فضای کاری تازه و خالی» را برای شروع
جدید انتخاب کنید، یا مسیر کامل پوشه دارای `Data` و `instance` را برای داده‌های
موجود وارد کنید. مسیر پیش‌فرض نمایش داده می‌شود. راه‌اندازی داده‌های موجود
مستلزم نسخه پشتیبان است؛ هیچ داده‌ای از محل نصب به آن کپی نمی‌شود.

۳. فقط در فضای تازه، نام کاربری، نام، ایمیل و گذرواژه نخستین مدیر فناوری اطلاعات
را تعیین کنید. حداقل طول گذرواژه ۱۲ نویسه است؛ حساب و گذرواژه پیش‌فرض وجود ندارد.
سپس صفحه ورود باز می‌شود. داده مالی، قیمت، سهم دسته، پیش‌بینی یا تاریخ برنامه‌ریزی
به‌صورت خودکار ساخته نمی‌شود. این ورودی‌ها را طبق جریان کاری تأییدشده وارد کنید.

۴. برای اجرای بعدی روی همان نشان کلیک کنید. اگر سامانه در حال اجرا باشد، مرورگر
همان نمونه تأییدشده را باز می‌کند. Python، pip، Git، Node، Docker، اینترنت یا
دستور دستی برای نصب/اجرای مشتری لازم نیست. مرورگر نصب‌شده و کتابخانه‌های معمول
سیستم‌عامل پیش‌نیاز هستند؛ بسته هیچ وابستگی را دانلود نمی‌کند.

## توقف

«کنترل و توقف سامانه» در صفحه ورود و سربرگ برنامه قرار دارد. روی «توقف سامانه»
کلیک کنید. میان‌بر توقف نیز در Start Menu ویندوز و action فهرست برنامه اوبونتو
وجود دارد. ذخیره‌سازی در حال اجرا تکمیل می‌شود؛ سپس سرور و قفل آزاد می‌شوند.
بستن مرورگر سرور را متوقف نمی‌کند. برای پایان کار از توقف استفاده کنید.

## داده و پشتیبان

* ویندوز: `%LOCALAPPDATA%\Engcost\workspace`؛ انتخاب فضای کاری در
  `%LOCALAPPDATA%\Engcost\config` نگهداری می‌شود.
* لینوکس: `$XDG_DATA_HOME/engcost/workspace` (پیش‌فرض
  `~/.local/share/engcost/workspace`) و `$XDG_CONFIG_HOME/engcost`
  (پیش‌فرض `~/.config/engcost`). فایل‌های runtime و log زیر فضای کاری/تنظیمات
  خصوصی هستند. مسیر دارای فاصله و نویسه فارسی پشتیبانی می‌شود.
* فضای انتخاب‌شده: `Data/` داده عملیاتی، `instance/app_data.json` کاربران و
  مجوزها، `instance/costing_period_bindings.json` اتصال دوره‌ها،
  `instance/standalone.json` کلید اختصاصی نشست و `instance/backups/` پشتیبان
  محدود سرویس Profile. `runtime/` و فایل‌های قفل قابل جایگزینی هستند؛ داده نیستند.

برای پشتیبان کامل، سامانه را متوقف کنید و کل `Data` و `instance` را به محل امن
کپی کنید. تنها پشتیبان Profile برای BOM و داده مالی کافی نیست. رمز عبور، hash
و کلید نشست را منتشر نکنید. پوشه نصب شامل داده مشتری نیست.

## داده موجود و بازیابی

انتخاب مستقیم داده موجود بدون کپی، شناسه‌ها، کاربران، نگاشت کارخانه، BOM، سهم‌ها،
پیش‌بینی‌ها و دوره‌ها را حفظ می‌کند. preflight فقط می‌خواند. هنگام فعال‌سازی،
دسترسی پوشه‌های خصوصی به مالک محدود می‌شود و مهاجرت/آماده‌سازی مصوب V2 از سرویس
موجود اجرا می‌شود. GET تحلیلی این آماده‌سازی را انجام نمی‌دهد. فضای موجود باید
Profile معتبر schema-v2 و پوشه‌های عملیاتی کارخانه ثبت‌شده داشته باشد؛ فضای قدیمی
ناسازگار را با رویه مصوب سرویس Profile، پیش از انتخاب، بررسی کنید.

اگر کپی لازم است، در حالت توقف کل فضای کاری را به **پوشه تازه** کپی کنید و نسخه
کپی را انتخاب کنید. مبدأ را تغییر ندهید. برنامه ابزار import ادغام‌کننده یا
بازنویسی‌کننده ندارد. فضای شبکه‌ای، پوشه sync، و symlink برای این نسخه اعتبارسنجی
نشده‌اند؛ preflight پیوندهای فایل/پوشه را رد می‌کند. از فضای محلی متعلق به خودتان
استفاده کنید.

در خرابی Profile، تنظیمات یا راه‌اندازی ناقص، برنامه داده را خالی فرض نمی‌کند،
مدیر جدید به کاربران موجود اضافه نمی‌کند و گذرواژه را بازنشانی نمی‌کند. پس از
توقف، از داده‌ها پشتیبان بگیرید؛ فایل خراب را از پشتیبان معتبر همان نصب بازیابی
کنید. کلید `standalone.json` را برای رفع خطا خودسرانه حذف نکنید. از راهنمای
[بازیابی و بررسی محصول](product-creation-owner-uat.md) برای تلاش‌های قدیمی استفاده
کنید؛ محصول تکراری خطای ۴۰۹ می‌دهد و فایل قبلی را حفظ می‌کند. گزارش خطای محلی
فقط نوع خطا/کد رویداد را ثبت می‌کند، نه گذرواژه یا قابلیت محلی.

اگر نصب متوقف شده است، نشان `.engcost-upgrading` مانع اجرای میان نسخه‌ها می‌شود.
نصب همان بسته سالم را دوباره اجرا کنید؛ در اوبونتو مدیر سیستم باید تراکنش ناقص
مدیر بسته را تکمیل کند. پوشه‌های `.next`/`.previous` در ویندوز فقط کد هستند؛
بدون بررسی، پوشه نامرتبط یا داده مشتری را حذف نکنید.

## ارتقا، بازگشت و حذف

ابتدا پشتیبان کامل بگیرید. installer فقط نمونه متعلق به Engcost را متوقف می‌کند،
منتظر پایان ذخیره‌ها می‌ماند و سپس کد را جایگزین می‌کند. نمونه ناشناس یا قفل
تأییدنشده کشته نمی‌شود؛ نصب متوقف می‌شود. اگر ذخیره بیش از ۶۰ ثانیه طول بکشد،
نصب را پس از پایان کار دوباره اجرا کنید. ارتقای آنلاین خودکار وجود ندارد.

برای بازگشت به بسته قبلی **سازگار**، همان installer قبلی را نصب کنید؛ داده مالی
را به‌دلیل تغییر کد عقب نبرید. آزمون بازگشت بین
دو نسخه مستقل هنوز انجام نشده است. نصب مجدد همین بسته و حذف آن در هر دو سیستم
آزمایش شده‌اند. uninstall داده، تنظیمات و کلید نشست را نگه
می‌دارد. حذف داده تنها اقدام جداگانه و آگاهانه مالک پس از پشتیبان است.

## ساخت و بررسی توسط توسعه‌دهنده

ساخت فقط روی همان OS/معماری، Python 3.12 x64 و محیط مجازی تمیز انجام می‌شود.
وابستگی‌ها و ابزارها در `requirements-packaging.txt` pin شده‌اند. NSIS 3.11 در
ویندوز و `dpkg-deb` در لینوکس لازم است؛ این‌ها ابزار سازنده هستند، نه مشتری.

```bash
python -m venv work/build-venv
work/build-venv/bin/python -m pip install -r requirements-packaging.txt
work/build-venv/bin/python scripts/vendor_offline_assets.py
work/build-venv/bin/python scripts/build_installers.py
```

در ویندوز از `work/build-venv/Scripts/python.exe` استفاده کنید. خروجی در
`work/pr11-artifacts/` شامل installer، `SHA256SUMS` و `build-info.json` است.
Build ماشین می‌تواند وابستگی تأییدشده دانلود کند. launcher چنین مسیری ندارد.
`packaging/engcost.spec` onedir است؛ منابع فقط از allowlist دارای hash
`packaging/resources.json` می‌آیند. build برنامه عملیاتی را import نمی‌کند.
Data، instance، work، evidence، cache، backup و credential checkout در bundle
وجود ندارند. ساخت تکرارپذیر به معنی ورودی/فرمان pin شده است؛ برابری بیت‌به‌بیت
بین میزبان‌ها یا فایل‌های امضاشده ادعا نمی‌شود.

برای Python 3.12.14 ویندوز، CI منبع CPython با SHA
`2abcf904b8dac8c999d2b3aac76681abb333798a` را با `PCbuild/build.bat -p x64 -c Release`
می‌سازد. نسخه 3.12.10 فقط ابزار bootstrap سازنده است؛ runtime مشتری 3.12.14 است.
فایل workflow فرمان‌های کامل را نگه می‌دارد. ساخت Ubuntu 22.04 از گزینه
`--max-glibc 2.35` برای جلوگیری از ABI جدیدتر استفاده می‌کند؛ بسته ساخته‌شده در
Debian این executor به GLIBC 2.38 نیاز دارد و برای Ubuntu 22.04 اعلام نمی‌شود.

CI مستقل Windows/Ubuntu بسته را نصب، executable نصب‌شده را اجرا، شبکه خارجی
را مسدود، صفحات desktop/mobile را ثبت و reinstall/uninstall را بررسی می‌کند.
تست harness به Python/Playwright نیاز دارد؛ فرایند مشتری با PATH جداشده و بدون
بسته‌های سیستم اجرا می‌شود. runner دارای ابزار توسعه است و جایگزین تست دستی
روی رایانه کاملاً تمیز Desktop نیست. artifactها و گزارش‌ها از Actions دریافت
می‌شوند؛ public release منتشر نمی‌شود.

بسته بدون امضا است. بررسی مجوز بازتوزیع فونت IRANSansX و Handsontable و UAT مالک
باقی است. [اعلان‌های طرف ثالث](../packaging/THIRD-PARTY-NOTICES.md) مجوز یا کلید
ساختگی ارائه نمی‌کنند.
